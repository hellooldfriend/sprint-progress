# Sprint Progress

Минималистичный трекер двухнедельных спринтов для тимлида кросс-функциональной команды.
Без бэкенда, без сборки, без Jira — открыл файл и работаешь.

## Запуск

```bash
open index.html
```

Всё работает прямо из файловой системы (`file://`) — сервер не нужен.
Если удобнее по http:

```bash
python3 -m http.server 4173
```

## Что умеет

**Спринты.** Создание (по умолчанию 14 дней, дата окончания подставляется сама), редактирование,
переключение в сайдбаре, закрытие в архив и возврат в работу. Архивный спринт открывается
в режиме просмотра: задачи не двигаются, метрики видны.

**Задачи.** Номер (`DEV-123`), название, тип, story points (опционально), флаг **Unplanned**,
исполнитель, дата добавления. Восемь статусов под полный цикл кросс-функциональной команды:

```
Backlog → To Do → In Progress → Review → Ready to Test → Testing → Deploy → Done
```

Закрытой считается только задача в **Done** — то, что висит в Deploy, остаётся в remaining
и в метрике «в работе».

**«Не закроем».** Флаг рядом с Unplanned (с причиной: перенос, отменили, заблокировано) —
для задач, которые в этом спринте точно не доедут. Снятие скоупа это решение тимлида,
а не стадия работы, поэтому это флаг, а не колонка на доске. Что он делает:

- задача уходит из **remaining work** и из требуемого темпа — burn-down честно доходит до нуля;
- на **burn-up** линия объёма падает в день снятия: видно, где скоуп урезали;
- процент закрытия по-прежнему считается от всего взятого объёма — снятием задач его не накрутить;
- в метриках появляется карточка «Не закроем» с разбивкой по причинам, в истории — колонка «Снято»
  и средний перенос за спринт;
- карточка остаётся в своей колонке, приглушённой: видно, на какой стадии задача застряла.

Задачу нельзя одновременно закрыть и снять: перевод в Done снимает флаг автоматически.

**Перенос между спринтами.** Задачи, которые не влезают в один спринт, лучше резать на
вертикальные срезы по ценности. Но если работа реально неделима (миграция, долгий рефакторинг,
внешняя блокировка), при закрытии спринта откроется диалог переноса:

- список незакрытых задач с чекбоксами и полем **остаточной оценки** — было 13 SP, осталось 8;
- цель: существующий активный спринт, новый (даты подставляются сразу после текущего) или «не переносить»;
- в закрываемом спринте задачи помечаются «Не закроем · Перенос», в новом создаются заново
  с сохранением номера, типа, исполнителя и **текущей стадии работы** — доделывать с того же места;
- перенесённая задача считается плановой работой нового спринта, а не unplanned.

Так velocity не задваивается: полная оценка не приезжает в новый спринт второй раз.
Плата за перенос — работа, сделанная в первом спринте, в его velocity не попадает.

**Закрытый спринт читается в прошедшем времени.** Дашборд архивного спринта переключает
формулировки: вместо «Осталось» — **«Не сделано»** (всё, что не в Done, включая снятое),
рядом «Перенесено», а под прогресс-баром итог вида
«Не сделано 21 SP, из них перенесено 16 SP → «Спринт 25»». На карточках перенесённых задач
вместо «Снято · Перенос» стоит стрелка с именем спринта-получателя.

Числа переноса в двух спринтах намеренно разные: закрытый спринт показывает, сколько **его**
объёма не доехало (13 SP исходной оценки), новый — сколько долга он **взял** (8 SP остатка).

**Задачи-долгожители.** У перенесённой задачи копится счётчик спринтов. Один перенос — тег
«Перенос из Спринт 24». Два и больше — тег «3-й спринт» оранжевым и предупреждение над доской:
задача, которая едет третий спринт подряд, почти всегда нарезана слишком крупно или заблокирована,
и её надо разбить или закрыть как отменённую. В метриках спринта появляется карточка
«Перенос из прошлого» (сколько взятого объёма — это долг), в истории — подстрока «перенос N · X%». Перетаскивание между колонками, стрелки `◂ ▸`
для быстрой смены статуса, клик по карточке — редактирование.

**Метрики.** Запланировано / незапланировано / выполнено / remaining, процент закрытия
с переключателем «story points ↔ задачи», velocity, темп в день и требуемый темп до конца спринта.
Крупный прогресс-бар с меткой «прошло времени» — сразу видно, отстаём мы или идём с опережением.

**Графики.** Burn-down (остаток против идеальной линии) и burn-up (сделанное против растущего
объёма — виден scope creep). История восстанавливается автоматически из дат создания и закрытия
задач, вручную ничего вбивать не нужно.

**История.** Средняя velocity, среднее закрытие, средняя доля внеплановой работы плюс таблица
всех спринтов с возможностью открыть любой прошлый.

**Данные.** Всё в `localStorage` этого браузера. Экспорт и импорт JSON — для бэкапа и переноса.

## Импорт задач

Кнопка «Массовый ввод» открывает импорт в двух режимах: строками и CSV из Jira.

### CSV из Jira

В Jira: поиск по JQL (`sprint = 42`) → Export → **Export CSV (current fields)**. Файл перетащите
в модалку, выберите кнопкой или вставьте содержимое текстом.

- **Колонки распознаются автоматически** по заголовкам (`Issue key`, `Summary`, `Issue Type`,
  `Status`, `Custom field (Story Points)`, `Assignee`) — русские заголовки тоже. Если угадалось
  не так, поправьте селектами: раскладка запомнится по именам колонок.
- **Статусы Jira** переводятся по встроенному словарю. Всё, чего в нём нет — «Ожидает релиза»,
  «Ждёт приёмки» — попадает в блок ручного сопоставления. Сопоставили один раз — запомнится
  навсегда, у каждой команды свой workflow.
- **Счётчик переносов заводится сам**: в выгрузке столько колонок `Sprint`, в скольких спринтах
  побывала задача, так что «едет 3-й спринт» посчитается по реальной истории Jira.
- **Повторная заливка обновляет, а не задваивает** — выгрузку можно перезаливать хоть каждый день.
  Обновляются название, тип, статус, оценка и исполнитель; новые задачи появляются.
  Локальные флаги существующих задач (**Unplanned**, «Не закроем», причина снятия) импорт **не трогает** —
  в выгрузке их нет, и перетирать ваши решения данными, которых в файле не существует, неправильно.
  Селект «Новые задачи — как» действует только на то, что создаётся этим импортом,
  и по умолчанию ставит Unplanned, если спринт уже идёт.
- **Колонка `Resolved`** (дата закрытия) подхватывается, если она есть в выгрузке — тогда burn-down
  строится по реальным датам закрытия, а не по моменту импорта. Понимает формат Jira
  (`13/Aug/26 3:04 PM`), локализованный (`13.08.2026 15:04`) и ISO.
- **Импорт ничего не удаляет.** Если задачу убрали из спринта в трекере, здесь она останется —
  предпросмотр покажет предупреждение со списком номеров, которых нет в файле.
- Понимает то, что реально отдаёт Jira: BOM, кавычки внутри значений, переводы строк в ячейке,
  разделитель `;` в локализованных выгрузках.

Чего в CSV нет и взяться неоткуда: флаг **Unplanned**, «Не закроем» и причина снятия — это
локальные понятия, Jira их не хранит. Что именно попало в спринт на планировании, а что прилетело
по ходу, в плоской выгрузке не написано: этот факт остаётся за вами.

Из-за этого объём спринта на графике строится так: **плановые задачи входят в объём с первого дня
спринта** независимо от того, когда вы их физически завели в инструменте (импорт в середине спринта
не создаёт ложную ступеньку), а **внеплановые — со дня появления**.

Прямого обращения к Jira API нет намеренно: Jira Cloud не отдаёт CORS-заголовки для авторизованных
запросов, а API-токен в `localStorage` статической страницы — это токен с полными правами учётки
в открытом виде. Живая синхронизация потребовала бы локального прокси, держащего токен у себя.

### Массовый ввод строками

Когда выгрузки нет под рукой — одна задача в строку, поля в порядке
`номер` `"название"` `тип` `статус` `story points`:

```
DEV-123 "Поменять название" Задача Готово 3
DEV-124 "Удалить логи" Задача "В процессе" 5
DEV-125 "Починить экспорт CSV" Баг Ревью 2
```

Правила разбора:

- **Название** — единственное обязательное поле. Если оно из нескольких слов, берите его в кавычки
  (`"…"`, `«…»`, `“…”`), иначе парсер не отличит его от типа.
- **Номер** распознаётся по виду `DEV-123`, `ПРО-45`, `ops_7`. Строка с уже существующим номером
  **обновит** задачу, а не создаст дубль — выгрузку из трекера можно перезаливать.
- **Статус** понимает русские и английские написания:

  | Колонка | Что распознаётся |
  |---|---|
  | Backlog | `Backlog`, `Бэклог` |
  | To Do | `To Do`, `К выполнению`, `Запланировано`, `Открыто`, `New` |
  | In Progress | `In Progress`, `В процессе`, `В работе`, `Doing` |
  | Review | `Review`, `Ревью`, `На ревью`, `Код-ревью`, `На проверке` |
  | Ready to Test | `Ready to Test`, `Ready for QA`, `Готово к тестированию`, `К тестированию` |
  | Testing | `Testing`, `QA`, `Тестирование`, `На тестировании` |
  | Deploy | `Deploy`, `Release`, `Staging`, `Деплой`, `Выкатка`, `Релиз` |
  | Done | `Done`, `Готово`, `Выполнено`, `Закрыто`, `Resolved` |

  Статус из нескольких слов можно писать и в кавычках (`"В процессе"`), и без них —
  парсер собирает до трёх слов с конца строки.
- **Тип** канонизируется по словарю (`баг`, `bug`, `ошибка` → `Баг`), незнакомый тип
  сохраняется как есть, если название взято в кавычки. Баги подсвечиваются на доске красным.
- **Story points** — последнее число в строке. Работает и старый формат `Название | 5`.
- `!` в начале строки помечает задачу как **Unplanned**.

Любое поле, кроме названия, можно опустить — статус и флаг Unplanned тогда возьмутся
из селектов под полем ввода. Что именно распозналось, видно в предпросмотре до нажатия «Добавить».

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `n` | Новая задача |
| `/` | Фокус в поиск по задачам |
| `Esc` | Закрыть модалку или меню |

## Структура

```
index.html      каркас интерфейса и модалки
css/styles.css  дизайн-система: токены, компоненты, адаптив
js/store.js     модель данных, localStorage, CRUD, экспорт/импорт
js/metrics.js   расчёт метрик и серий для графиков (чистые функции)
js/charts.js    SVG-графики без внешних библиотек
js/ui.js        рендер интерфейса
js/app.js       события, drag & drop, модалки, бутстрап
```

При первом открытии данных нет — создайте спринт и залейте задачи массовым вводом.
